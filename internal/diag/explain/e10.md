# E10xx–E11xx — extensions, version compatibility

## E1002

The extension refers to an entity, actor or view missing from the base model. Only existing declarations can be extended; an extension declares new types the usual way.

```rr
aggregate Order
  id uuid

# file: extensions/acme/order.rr
extend Ordr
  note string?
```

```rr
aggregate Order
  id uuid

# file: extensions/acme/order.rr
extend Order
  note string?
```

## E1003

An extension can only add new members: a field, method or index named like a base member would change the base model's behaviour. Only rules can be overridden.

```rr
aggregate Order
  id uuid
  status int

# file: extensions/acme/order.rr
extend Order
  status string
```

```rr
aggregate Order
  id uuid
  status int

# file: extensions/acme/order.rr
extend Order
  acmeStatus string
```

## E1004

An overridden rule must keep the base signature: the same parameters (names and types) and result type. Otherwise base commands cannot call it.

```rr
aggregate Order
  id uuid
  price decimal

  rule rate(vip bool) decimal
    return 30

  command(admin) Price(vip bool)
    priced(amount: rate(vip: vip))

  event priced(amount decimal)
    price = amount

role admin

# file: extensions/acme/order.rr
extend Order
  rule rate(vip bool) int
    return 25
```

```rr
aggregate Order
  id uuid
  price decimal

  rule rate(vip bool) decimal
    return 30

  command(admin) Price(vip bool)
    priced(amount: rate(vip: vip))

  event priced(amount decimal)
    price = amount

role admin

# file: extensions/acme/order.rr
extend Order
  rule rate(vip bool) decimal
    return 25
```

## E1005

The extension overrides a rule the base model does not declare. An extension changes only declared extension points; new logic comes as commands and on reactions.

```rr
aggregate Order
  id uuid

# file: extensions/acme/order.rr
extend Order
  rule discount() decimal
    return 5
```

```rr
aggregate Order
  id uuid

  rule discount() decimal
    return 0

# file: extensions/acme/order.rr
extend Order
  rule discount() decimal
    return 5
```

## E1006

An on reaction refers to an event the entity does not have, neither in the base model nor in the extension.

```rr
aggregate Order
  id uuid

  command(admin) Place()
    placed()

  event placed()

role admin

# file: extensions/acme/order.rr
extend Order
  on plased
    return
```

```rr
aggregate Order
  id uuid

  command(admin) Place()
    placed()

  event placed()

role admin

# file: extensions/acme/order.rr
extend Order
  on placed
    return
```

## E1007

exclude test removes a base test that does not hold for the extension. The base model has no test with this name — check the name.

```rr
actor Customer
  id uuid

  command(self) SignUp()
    return

test "Sign-up"
  let c1 = new Customer.Id
  when
    [c1].SignUp() as c1

# file: extensions/acme/tests.rr
exclude test "Sign-upp" because "sign-in through SSO"
```

```rr
actor Customer
  id uuid

  command(self) SignUp()
    return

test "Sign-up"
  let c1 = new Customer.Id
  when
    [c1].SignUp() as c1

# file: extensions/acme/tests.rr
exclude test "Sign-up" because "sign-in through SSO"
```

## E1009

extend and exclude belong only in extension files under extensions/<name>/. In the base model, add members to the declaration itself.

```rr
aggregate Order
  id uuid

extend Order
  note string?
```

```rr
aggregate Order
  id uuid
  note string?
```

## E1010

The base model writes projection rows whole: fields it does not pass get their default values (E0305). A field added by an extension would be reset by every such write, so a projection cannot be extended. An extension keeps its data in a projection of its own.

```rr
aggregate Order
  id uuid

projection OrderMart
  id Order.Id

# file: extensions/acme/order.rr
extend OrderMart
  costCenter string?
```

```rr
aggregate Order
  id uuid

projection OrderMart
  id Order.Id

# file: extensions/acme/order.rr
projection CostMart
  id Order.Id
  costCenter string?
```

## E1011

A screen extension adds lines to a part: in Actions — into the line of part Actions on the screen. The screen has several such lines (two cards with Actions), and the compiler does not know which one to extend. Split the screen or move the card to a screen of its own.

```rr
value Profile
  name string?

actor Customer
  id uuid
  name string?

  command(self) Rename(newName string)
    renamed(newName: newName)

  event renamed(newName string)
    name = newName

  query(Customer) Me() Profile
    return Profile(name: none)

app(Customer) Shop
  Menu
    Home

screen Home
  Card Customer.Me
    Actions
      Edit Customer.Rename
  Card Customer.Me
    Actions
      Edit Customer.Rename

# file: extensions/acme/home.rr
extend screen Home
  in Actions
    Edit Customer.Rename
```

```rr
value Profile
  name string?

actor Customer
  id uuid
  name string?

  command(self) Rename(newName string)
    renamed(newName: newName)

  event renamed(newName string)
    name = newName

  query(Customer) Me() Profile
    return Profile(name: none)

app(Customer) Shop
  Menu
    Home

screen Home
  Card Customer.Me
    Actions
      Edit Customer.Rename

# file: extensions/acme/home.rr
extend screen Home
  in Actions
    Edit Customer.Rename
```

## E1101

The change is incompatible with already stored data: a field type, id strategy or type kind changed, or an enum value was removed. The engine cannot read old data on its own — add a manual migration that converts it.

```rr
# file: old/m.rr
aggregate Order
  id uuid
  total int

# file: new/m.rr
aggregate Order
  id uuid
  total decimal
```

```rr
# file: old/m.rr
aggregate Order
  id uuid
  total int

# file: new/m.rr
aggregate Order
  id uuid
  total decimal

  command recalc()
    return

migration recalcTotals
  for order in all Order
    [order].recalc()
```

## E1102

Stored events are read forever: an event cannot be removed or renamed, and an argument cannot be removed or change type. A new argument is fine if it has a default or is optional. For a new meaning, declare a new event.

```rr
# file: old/m.rr
role admin

aggregate Order
  id uuid
  total int

  command(admin) Pay(sum int)
    paid(sum: sum)

  event paid(sum int)
    total = sum

# file: new/m.rr
role admin

aggregate Order
  id uuid
  total int

  command(admin) Pay(sum int, promo string)
    paid(sum: sum, promo: promo)

  event paid(sum int, promo string)
    total = sum
```

```rr
# file: old/m.rr
role admin

aggregate Order
  id uuid
  total int

  command(admin) Pay(sum int)
    paid(sum: sum)

  event paid(sum int)
    total = sum

# file: new/m.rr
role admin

aggregate Order
  id uuid
  total int

  command(admin) Pay(sum int, promo string)
    paid(sum: sum, promo: promo)

  event paid(sum int, promo string = "")
    total = sum
```

## E1104

A method, parameter, field or enum value that clients of a released external API version (api/versions/<date>.json) see has disappeared from the model. Those clients are released separately and will get an error. If you renamed it, mark the new name with the old one via was: the engine will accept and return the old name to that version's clients. Published items may be removed only after deprecation: reasonr api deprecate Method --sunset date, and after that date.

```rr skip
# api/versions/2026-11-12.json: Order.Cancel(reason string)
aggregate Order
  id uuid

  command(admin) Cancel(cancelReason string)
    cancelled()
```

```rr skip
aggregate Order
  id uuid

  command(admin) Cancel(cancelReason string was reason)
    cancelled()
```

## E1105

A published method got a required parameter without a default. Clients of a released version do not pass it, so their calls would fail. Give the parameter a default (then the old version does not see it) or declare a new method next to the old one.

```rr skip
aggregate Order
  id uuid

  command(admin) Pay(amount decimal, currency string)
    paid()
```

```rr skip
aggregate Order
  id uuid

  command(admin) Pay(amount decimal, currency string = "rub")
    paid()
```

## E1106

The type of a parameter, result or field that clients of a released version see changed in a way old clients cannot pass or read. Only widening is allowed: a required parameter may become optional. For a different type, declare a new method or field next to the old one.

```rr skip
aggregate Order
  id uuid

  command(admin) Tip(amount string)
    tipped()
```

```rr skip
aggregate Order
  id uuid

  command(admin) Tip(amount decimal)
    tipped()

  command(admin) TipText(text string)
    tipped()
```

## E1107

api/contract.json publishes a method the model does not have: a typo, a removed method or a private command. Only a public (capitalized) command or query can be published: Ordering.Order.Cancel, or all methods of a type, Ordering.Order.*.

```rr skip
# api/contract.json: {"publish": ["Ordering.Order.Cancle"]}
aggregate Order
  id uuid
```

```rr skip
# api/contract.json: {"publish": ["Ordering.Order.Cancel"]}
aggregate Order
  id uuid
```
