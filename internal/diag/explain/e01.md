# E01xx — names

## E0101

The name is already taken in the module. Entities, actors, projections, values, enums, external systems, views and controls share one namespace, roles have their own; migration names and test names must be unique too.

```rr
aggregate Order
  id uuid

value Order
  amount decimal
```

```rr
aggregate Order
  id uuid

value OrderTotal
  amount decimal
```

## E0102

The type already has a member with this name in the same namespace: two fields, two indexes or two methods (commands, events, notifications, errors, queries, rules) with one name. In a value, fields and methods share one namespace: both read as x.name.

```rr
aggregate Order
  id uuid
  status int
  status string
```

```rr
aggregate Order
  id uuid
  status int
  statusText string
```

## E0103

A parameter or variable has the same name as a field. Fields, parameters and variables have distinct names so that driver = driverId reads unambiguously: the field on the left, the argument on the right.

```rr
aggregate Order
  id uuid
  status int
  previous int

  event changed(status int)
    previous = status
```

```rr
aggregate Order
  id uuid
  status int
  previous int

  event changed(newStatus int)
    previous = newStatus
```

## E0104

The name is already declared above in the same method: method parameters and variables neither repeat nor shadow each other in nested blocks. Give the second variable its own name.

```rr
aggregate Account
  id uuid
  balance decimal

  command touch(amount decimal)
    let amount = 2
    return
```

```rr
aggregate Account
  id uuid
  balance decimal

  command touch(amount decimal)
    let doubled = amount * 2
    return
```

## E0105

The name matches both a variable, field or parameter and a value of the expected enum. The variable wins, but the code reads ambiguously — write the value in full: Type.value.

```rr
enum Status
  active
  closed

aggregate Account
  id uuid
  status Status
  active bool

  command close()
    if status == active
      return
```

```rr
enum Status
  active
  closed

aggregate Account
  id uuid
  status Status
  active bool

  command close()
    if status == Status.active
      return
```

## E0106

The case of the first letter defines what a name is. Types and public commands and queries start with an uppercase letter; fields, parameters, variables, events, errors, notifications, rules, roles, enum values and private methods start with a lowercase letter.

```rr
aggregate Account
  id uuid
  Balance decimal
```

```rr
aggregate Account
  id uuid
  balance decimal
```

## E0107

No declared or built-in type has this name. Check the spelling: the compiler suggests the closest name. An entity id is written with a dot — Order.Id, a timer id — Timer.Id.

```rr
aggregate Account
  id uuid
  balance decimel
```

```rr
aggregate Account
  id uuid
  balance decimal
```

## E0108

The name belongs to a built-in value: id, now, today, after, hasErrors, me, caller, self. A field, parameter or variable with this name would hide it.

```rr
aggregate Order
  id uuid
  now timestamp
```

```rr
aggregate Order
  id uuid
  createdAt timestamp
```

## E0109

A built-in generic type has the wrong number of arguments: list<T>, set<T> and page<T> take one type, map<K, V> takes two; other types take none.

```rr
aggregate Order
  id uuid
  tags list
```

```rr
aggregate Order
  id uuid
  tags list<string>
```

## E0110

Entities, actors and projections must declare id: it defines the id type — id uuid, id sequence, id string, id <value> or, for a projection, id <Entity>.Id.

```rr
aggregate Order
  status int
```

```rr
aggregate Order
  id uuid
  status int
```

## E0111

The id is declared incorrectly. Entities and actors use uuid, sequence, string or a value (a composite key); id <Entity>.Id is only for projections and must refer to an entity, not another projection.

```rr
aggregate Customer
  id uuid

aggregate Order
  id Customer.Id
```

```rr
aggregate Customer
  id uuid

aggregate Order
  id uuid
```
