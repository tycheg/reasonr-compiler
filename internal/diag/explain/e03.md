# E03xx–E06xx — bounded contexts, call graph, queries and indexes, access

## E0301

Entity fields change only in events. A command raises an event and the event assigns the fields: every state change is recorded as a fact and can be replayed.

```rr
aggregate Order
  id uuid
  status int

  command close()
    status = 2
```

```rr
aggregate Order
  id uuid
  status int

  command close()
    closed()

  event closed()
    status = 2
```

## E0302

An event body consists only of field assignments. Events have no branches, loops, calls, now or new: replaying them must give the same result. The command makes decisions; the event only records them.

```rr
aggregate Order
  id uuid
  status int

  event closed(final bool)
    if final
      status = 2
```

```rr
aggregate Order
  id uuid
  status int

  event closed(newStatus int)
    status = newStatus
```

## E0303

This action is not allowed in this kind of body. Commands and reactions raise events, call commands, send notifications and external requests and schedule timers; queries only read data; rules and value methods are pure functions; type searches exist only in queries.

```rr
aggregate Order
  id uuid
  status int

  rule rate() int
    closed()
    return 1

  event closed()
    status = 2
```

```rr
aggregate Order
  id uuid
  status int

  rule rate() int
    return 1

  command close()
    closed()

  event closed()
    status = 2
```

## E0304

The built-in value is not available here: events have no now or today (they must replay identically), rules and methods have nothing that depends on execution, queries have no id or after (a query belongs to the type), me exists only in methods accessible to one actor.

```rr
aggregate Order
  id uuid
  closedAt timestamp

  event closed()
    closedAt = now
```

```rr
aggregate Order
  id uuid
  closedAt timestamp

  command close()
    closed(at: now)

  event closed(at timestamp)
    closedAt = at
```

## E0305

A projection row is written whole: pass every field except optional ones (T?) and fields with an explicit '= value'. A field left out gets its default value instead of keeping the old one, so one entity writes the row — the one that has all of the row's data; data of other entities reaches it through command arguments. This way the engine needs no write order: a row has a version, and a late write does not overwrite a newer one.

```rr
aggregate Order
  id uuid
  status int
  placedAt timestamp

  command ship()
    shipped()
    Mart(id: Mart.Id(id), status: status)

  event shipped()
    status = 2

projection Mart
  id Order.Id
  status int
  placedAt timestamp
```

```rr
aggregate Order
  id uuid
  status int
  placedAt timestamp

  command ship()
    shipped()
    Mart(id: Mart.Id(id), status: status, placedAt: placedAt)

  event shipped()
    status = 2

projection Mart
  id Order.Id
  status int
  placedAt timestamp
```

## E0401

Commands call each other in a cycle (also through on reactions). Command recursion is forbidden: a unit of work must terminate. To repeat an action later, use a timer — it runs as a separate unit of work.

```rr
aggregate Order
  id uuid

  command retry()
    retry()
```

```rr
aggregate Order
  id uuid
  timer Timer.Id?

  command retry()
    let t = schedule(at: now + 1m, run: retry())
    retried(t: t)

  event retried(t Timer.Id)
    timer = t
```

## E0402

In schedule(at: …, run: …), run must be a call of a command of this entity: the timer runs it later on behalf of the entity. Events, errors and other entities' commands cannot be scheduled.

```rr
aggregate Order
  id uuid
  timer Timer.Id?

  command start()
    let t = schedule(at: now + 1m, run: started(t: timer))
    return

  event started(t Timer.Id?)
    timer = t
```

```rr
aggregate Order
  id uuid
  timer Timer.Id?

  command start()
    let t = schedule(at: now + 1m, run: expire())
    started(t: t)

  command expire()
    return

  event started(t Timer.Id?)
    timer = t
```

## E0501

A search condition is a set of "field operator value" conditions joined with and, so it can run on an index. or, not, comparing two fields and conditions without a record field are not index-friendly; split the search or use in.

```rr
value Row
  title string

aggregate Item
  id uuid
  status string
  title string

  index byStatus(status)

  query Find() list<Row>
    return [Item]
      where status == "a" or status == "b"
      limit 10
      select Row(title: title)
```

```rr
value Row
  title string

aggregate Item
  id uuid
  status string
  title string

  index byStatus(status)

  query Find() list<Row>
    return [Item]
      where status in ["a", "b"]
      limit 10
      select Row(title: title)
```

## E0502

The value on the right of a search condition cannot depend on the record: use parameters, me, now and literals. "field == expression of fields" cannot run on an index.

```rr
value Row
  total int

aggregate Item
  id uuid
  total int
  limitValue int

  index byTotal(total)

  query Find() list<Row>
    return [Item]
      where total == limitValue + 1
      limit 10
      select Row(total: total)
```

```rr
value Row
  total int

aggregate Item
  id uuid
  total int
  limitValue int

  index byTotal(total)

  query Find(wanted int) list<Row>
    return [Item]
      where total == wanted + 1
      limit 10
      select Row(total: total)
```

## E0503

An index cannot search by "not equal" (!= and is not none): such a search reads almost the whole table. List the acceptable values with in.

```rr
value Row
  title string

aggregate Item
  id uuid
  status string
  title string

  index byStatus(status)

  query Find() list<Row>
    return [Item]
      where status != "closed"
      limit 10
      select Row(title: title)
```

```rr
value Row
  title string

aggregate Item
  id uuid
  status string
  title string

  index byStatus(status)

  query Find() list<Row>
    return [Item]
      where status in ["new", "open"]
      limit 10
      select Row(title: title)
```

## E0504

No index fits the search. An index fits when equalities cover a prefix of its keys, a range (<, <=, >, >=) is on the next key, and sorting continues the keys in the same or fully reversed order. The compiler suggests an index and can insert it.

```rr
value Row
  title string

aggregate Item
  id uuid
  owner string
  title string

  query Mine(who string) list<Row>
    return [Item]
      where owner == who
      sort title
      limit 10
      select Row(title: title)
```

```rr
value Row
  title string

aggregate Item
  id uuid
  owner string
  title string

  index byOwnerTitle(owner, title)

  query Mine(who string) list<Row>
    return [Item]
      where owner == who
      sort title
      limit 10
      select Row(title: title)
```

## E0505

A search returns a page (page) or a bounded list (limit ≤ 100). An unbounded result is small today and the whole table tomorrow.

```rr
value Row
  title string

aggregate Item
  id uuid
  title string

  index byTitle(title)

  query All() list<Row>
    return [Item]
      sort title
      select Row(title: title)
```

```rr
value Row
  title string

aggregate Item
  id uuid
  title string

  index byTitle(title)

  query All(pageReq PageRequest) page<Row>
    return [Item]
      sort title
      page pageReq
      select Row(title: title)
```

## E0506

limit is at most 100. For larger results use page: the client gets a cursor and asks for the next page.

```rr

aggregate Item

  query Top() list<Row>
    return [Item]
      sort title
      limit 500
      select Row(title: title)
```

```rr

  title string

  index byTitle(title)

  query Top() list<Row>
    return [Item]

```

## E0507

On every path a query returns a value or raises an error before return: the client must get a result or a reason why there is none.

```rr
value Card
  title string

aggregate Item
  id uuid
  title string

  query(admin) Show(itemId Item.Id) Card
    let it = [itemId]
    if it is none
      return
    return Card(title: it.title)

role admin
```

```rr
value Card
  title string

aggregate Item
  id uuid
  title string

  error notFound

  query(admin) Show(itemId Item.Id) Card
    let it = [itemId]
    if it is none
      notFound()
      return
    return Card(title: it.title)

role admin
```

## E0508

Rules and value methods are functions: they return a value on every execution path.

```rr
aggregate Order
  id uuid

  rule rate(vip bool) int
    if vip
      return 10
```

```rr
aggregate Order
  id uuid

  rule rate(vip bool) int
    if vip
      return 10
    return 20
```

## E0509

A query returns a value, page<value> or list<value>. Entity records are never returned as is: the value defines the response contract and hides extra fields.

```rr
aggregate Item
  id uuid
  total int

  query(admin) Total() int
    return 1

role admin
```

```rr
value TotalRow
  total int

aggregate Item
  id uuid
  total int

  query(admin) Total() TotalRow
    return TotalRow(total: 1)

role admin
```

## E0510

Records of a type are read only in queries of that type: the data owner is responsible for reads and indexes stay in one place. To get another type's data, call its query.

```rr
value Card
  title string

aggregate Item
  id uuid
  title string

aggregate Shelf
  id uuid

  query(admin) Peek(itemId Item.Id) Card
    let it = [itemId]
    return Card(title: "x")

role admin
```

```rr
value Card
  title string

aggregate Item
  id uuid
  title string

  error notFound

  query(admin) Show(itemId Item.Id) Card
    let it = [itemId]
    if it is none
      notFound()
      return
    return Card(title: it.title)

aggregate Shelf
  id uuid

  query(admin) Peek(itemId Item.Id) Card
    return Item.Show(itemId: itemId)

role admin
```

## E0511

A unique index names an error the type does not declare. Declare the error: the client receives it when the value is already taken.

```rr
actor Customer
  id uuid
  phone string

  index byPhone(phone) unique phoneTaken
```

```rr
actor Customer
  id uuid
  phone string

  index byPhone(phone) unique phoneTaken

  error phoneTaken(phone string)
```

## E0512

The engine fills the parameters of a unique-index error with key values, so each parameter is named after the last segment of a key path and has its type.

```rr
actor Customer
  id uuid
  phone string

  index byPhone(phone) unique phoneTaken

  error phoneTaken(number string)
```

```rr
actor Customer
  id uuid
  phone string

  index byPhone(phone) unique phoneTaken

  error phoneTaken(phone string)
```

## E0601

self in an access list means "the actor itself": it is only valid for actor commands and queries. An entity uses a field holding an actor id, an actor type or a role.

```rr
aggregate Order
  id uuid

  command(self) Cancel()
    return
```

```rr
actor Customer
  id uuid

aggregate Order
  id uuid
  customer Customer.Id?

  command(customer) Cancel()
    return
```

## E0602

A field in an access list must hold an actor id (Customer.Id or Customer.Id?): the command may be called by the actor whose id is stored there.

```rr
aggregate Order
  id uuid
  status int

  command(status) Close()
    return
```

```rr
actor Customer
  id uuid

aggregate Order
  id uuid
  customer Customer.Id?

  command(customer) Close()
    return
```

## E0603

A name in an access list is both a role and a field — it is unclear which is meant. Rename the field.

```rr
role customer

actor Buyer
  id uuid

aggregate Order
  id uuid
  customer Buyer.Id?

  command(customer) Pay()
    return
```

```rr
role customer

actor Buyer
  id uuid

aggregate Order
  id uuid
  buyer Buyer.Id?

  command(buyer) Pay()
    return
```

## E0604

A name in an access list was not found: expected self, a field holding an actor id, an actor type or a role. The compiler suggests the closest name.

```rr
role admin

aggregate Order
  id uuid

  command(admn) Refund()
    return
```

```rr
role admin

aggregate Order
  id uuid

  command(admin) Refund()
    return
```

## E0605

Access lists are only for public methods (uppercase). Private commands are called by other commands and timers, there is no access to check.

```rr
role admin

aggregate Order
  id uuid

  command(admin) close()
    return

  command(admin) Close()
    close()
```

```rr
role admin

aggregate Order
  id uuid

  command close()
    return

  command(admin) Close()
    close()
```

## E0606

Field-based access exists only for commands: a query belongs to the type, not an instance, so entity fields are unknown when checking access. Check the owner inside the query using me.

```rr
value Card
  total int

actor Customer
  id uuid

aggregate Order
  id uuid
  customer Customer.Id?
  total int

  query(customer) Show(orderId Order.Id) Card
    return Card(total: 0)
```

```rr
value Card
  total int

actor Customer
  id uuid

aggregate Order
  id uuid
  customer Customer.Id?
  total int

  error notFound

  query(Customer) Show(orderId Order.Id) Card
    let o = [orderId]
    if o is none or o.customer != me
      notFound()
      return
    return Card(total: o.total)
```
