# E14xx — project structure

## E1401

Project sources are laid out in parts: contexts (contexts/<Context>/), apps (apps/<App>/) and primitives (primitives/). A file in the source root, directly in contexts/ or directly in apps/ belongs to no part. Move it into the directory of its part; a module without these directories is flat, and then its files lie in the root.

```rr
# file: contexts/Sales/order.rr
aggregate Order
  id uuid

# file: customer.rr
aggregate Customer
  id uuid
```

```rr
# file: contexts/Sales/order.rr
aggregate Order
  id uuid

# file: contexts/Sales/customer.rr
aggregate Customer
  id uuid
```

## E1402

A context directory is named after the context: one capitalized word like a type name — Ordering, Billing. A context is a one-level namespace: its declarations are named Ordering.Order, Ordering.Money.

```rr
# file: contexts/ordering/order.rr
aggregate Order
  id uuid
```

```rr
# file: contexts/Ordering/order.rr
aggregate Order
  id uuid
```

## E1403

An app is named after its directory: apps/<App>/ declares exactly one app with that name, next to its texts. Move a second app into a directory of its own.

```rr
# file: contexts/Sales/order.rr
role admin

screen Home "Home"
  Link Home

# file: apps/Admin/app.rr
app(admin) Backoffice "Admin"
  Menu
    Home
```

```rr
# file: contexts/Sales/order.rr
role admin

screen Home "Home"
  Link Home

# file: apps/Admin/app.rr
app(admin) Admin "Admin"
  Menu
    Home
```

## E1404

Each declaration has its project part: an app goes to apps/<App>/, primitives and default for all apps go to primitives/, everything else — the model, ACLs, screens, tests, fakes — goes to a context contexts/<Context>/. Texts may be written in any part.

```rr
# file: contexts/Sales/order.rr
role admin

screen Home "Home"
  Link Home

app(admin) Admin "Admin"
  Menu
    Home
```

```rr
# file: contexts/Sales/order.rr
role admin

screen Home "Home"
  Link Home

# file: apps/Admin/app.rr
app(admin) Admin "Admin"
  Menu
    Home
```

## E1406

A context is a namespace, and a short name must point to one thing: a type or a context. So a type is not named like a context of the project; rename the type.

```rr
# file: contexts/Sales/order.rr
value Sales
  total decimal
```

```rr
# file: contexts/Sales/order.rr
value SalesTotal
  total decimal
```

## E1407

A context owns its model: its ids, types and methods work only inside it. Another context sees that model only in its own ACL (an *.acl.rr file, acl Source): entities and actors — their ids, events for on reactions and public commands — as well as values and enums. Fields, projections, queries and external systems of the source are closed even in the ACL: the receiver keeps the data it needs from events. Outside contexts — in apps and tests — everything is visible. Translate the source model into yours in an ACL.

```rr
# file: contexts/Sales/order.rr
aggregate Order
  id uuid

  command place()
    placed()

  event placed()

# file: contexts/Delivery/parcel.rr
aggregate Parcel
  id uuid
  order Sales.Order.Id?
```

```rr
# file: contexts/Sales/order.rr
aggregate Order
  id uuid

  command place()
    placed()

  event placed()

# file: contexts/Delivery/parcel.rr
aggregate Parcel
  id uuid

  command open()
    opened()

  event opened()

# file: contexts/Delivery/sales.acl.rr
acl Sales
  on Sales.Order.placed
    [Parcel.Id(id)].open()
```

## E1415

```rr
  id uuid
```

## E1417

actor Source.Actor as Actor — a calling actor of the source context (given by authentication) acts in your context as its actor with the same id: it passes self and (Actor) access, and me is your context's actor. The left side is an actor of the source, the right side an actor of your context; both have the same id kind (uuid and uuid).

```rr
# file: contexts/Accounts/user.rr
actor User
  id uuid

# file: contexts/Shop/customer.rr
actor Customer
  id string

# file: contexts/Shop/accounts.acl.rr
acl Accounts
  actor Accounts.User as Customer
```

```rr
# file: contexts/Accounts/user.rr
actor User
  id uuid

# file: contexts/Shop/customer.rr
actor Customer
  id uuid

# file: contexts/Shop/accounts.acl.rr
acl Accounts
  actor Accounts.User as Customer
```

## E1418

Enum(x) in an ACL translates a value of the source enum into the value of your enum with the same name. So your enum must have every value of the source enum; when the names differ, translate the values with a condition.

```rr
# file: contexts/Sales/order.rr
enum Speed
  normal
  express

aggregate Order
  id uuid

  event placed(speed Speed)

# file: contexts/Delivery/parcel.rr
enum Speed
  normal

aggregate Parcel
  id uuid

  command open(speed Speed)
    opened(speed: speed)

  event opened(speed Speed)

# file: contexts/Delivery/sales.acl.rr
acl Sales
  on Sales.Order.placed
    [Parcel.Id(id)].open(speed: Speed(speed))
```

```rr
# file: contexts/Sales/order.rr
enum Speed
  normal
  express

aggregate Order
  id uuid

  event placed(speed Speed)

# file: contexts/Delivery/parcel.rr
enum Speed

    opened(speed: speed)

  event opened(speed Speed)

# file: contexts/Delivery/sales.acl.rr

  on Sales.Order.placed
```

## E1419

An aggregate, a consistency boundary, is declared at the top level of a context: aggregate Order. Its inner entities are declared with the aggregate name, entity Order.Stop, and live inside it. There is no top-level entity: replace it with aggregate.

```rr
entity Order
  id uuid
```

```rr
aggregate Order
  id uuid
```

## E1421

Public commands and queries belong to the aggregate: a client calls the aggregate, and it calls its inner entities. An inner entity has only private commands, events and errors; it has no queries or indexes, since it is stored in the aggregate's document.

```rr
role admin

aggregate Order
  id uuid

  command(admin) AddStop()
    [new Stop.Id].add()

entity Order.Stop
  id sequence

  command add()
    added()

  command(admin) Visit()
    added()

  event added()
```

```rr
role admin

aggregate Order
  id uuid

  command(admin) AddStop()
    [new Stop.Id].add()

  command(admin) Visit(stop Stop.Id)
    [stop].visit()

entity Order.Stop
  id sequence

  command add()
    added()

  command visit()
    added()

  event added()
```

## E1422

An inner entity is addressed only inside its aggregate: [stop], [Stop] and its commands are available to the commands, rules and reactions of the aggregate and its inner entities, which have an aggregate instance. From outside, call a public command of the aggregate with the inner entity id.

```rr
role admin

aggregate Order
  id uuid

  command(admin) AddStop()
    [new Stop.Id].add()

  query(admin) Count(orderId Order.Id) StopCount
    let n = 0
    for s in [Stop]
      n = n + 1
    return StopCount(stops: n)

value StopCount
  stops int

entity Order.Stop
  id sequence

  command add()
    added()

  event added()
```

```rr
role admin

aggregate Order
  id uuid
  stops int

  command(admin) AddStop()
    [new Stop.Id].add()
    counted()

  query(admin) Count(orderId Order.Id) StopCount
    let o = [orderId]
    if o is none
      return StopCount(stops: 0)
    return StopCount(stops: o.stops)

  event counted()
    stops = stops + 1

value StopCount
  stops int

entity Order.Stop
  id sequence

  command add()
    added()

  event added()
```

## E1423

An inner entity id means something only next to its aggregate id, so only the aggregate itself and its inner entities store and pass it, in fields, events, parameters and results. A value may contain such an id, but such a value in another aggregate is an error. Refer to the aggregate.

```rr
aggregate Order
  id uuid

entity Order.Stop
  id sequence

aggregate Courier
  id uuid
  stop Order.Stop.Id?
```

```rr
aggregate Order
  id uuid

entity Order.Stop
  id sequence

aggregate Courier
  id uuid
  order Order.Id?
```

## E1424

A create command, command(access) create Name, is called without an id: the engine issues it by the aggregate's strategy and returns it in the response. So it is public, belongs to an aggregate, and the aggregate has id uuid or id sequence. With an id given by the caller (id string), the aggregate is created by its first command.

```rr
role admin

aggregate Tag
  id string

  command(admin) create Make()
    made()

  event made()
```

```rr
role admin

aggregate Tag
  id sequence

  command(admin) create Make()
    made()

  event made()
```
