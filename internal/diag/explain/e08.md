# E08xx–E09xx — tests, personal data

## E0801

given prepares state the way a user would: only public command calls and time passes. Private commands, queries and other actions are not allowed.

```rr
actor Customer
  id uuid

  command(self) SignUp()
    return

  command note()
    return

test "Sign-up"
  let c1 = new Customer.Id
  given
    [c1].note() as c1
  when
    [c1].SignUp() as c1
```

```rr
actor Customer
  id uuid

  command(self) SignUp()
    return

test "Sign-up"
  let c1 = new Customer.Id
  given
    time offset +1s
  when
    [c1].SignUp() as c1
```

## E0802

when has exactly one action: a public command, a public query or time passes. A test checks one behaviour; preparation goes into given.

```rr
actor Customer
  id uuid

  command(self) SignUp()
    return

  command(self) Leave()
    return

test "Sign-out"
  let c1 = new Customer.Id
  when
    [c1].SignUp() as c1
    [c1].Leave() as c1
```

```rr
actor Customer
  id uuid

  command(self) SignUp()
    return

  command(self) Leave()
    return

test "Sign-out"
  let c1 = new Customer.Id
  given
    [c1].SignUp() as c1
  when
    [c1].Leave() as c1
```

## E0804

A then check refers to something that does not exist: an undeclared error or notification, an unknown external request, a field missing from the query result, or matches without a query in when.

```rr
actor Customer
  id uuid

  command(self) SignUp()
    alreadyRegistered()

  error alreadyRegistered

test "Repeated sign-up"
  let c1 = new Customer.Id
  when
    [c1].SignUp() as c1
  then
    error alreadyRegisterd
```

## E0805

A demo scenario (`*.demo.rr`, RFC §27.5) fills a tenant with plausible data: it has a single `given` section with steps, loops and `time offset`. `when` and `then` checks belong to `*.test.rr` acceptance tests.

```rr
# file: customers.demo.rr
actor Customer
  id uuid

  command(self) SignUp()
    signedUp()

  event signedUp()

test "Customers"
  given
    for i in range(3)
      let c = new Customer.Id
      [c].SignUp() as c
  when
    time offset +1h
```

```rr
# file: customers.demo.rr
actor Customer

  command(self) SignUp()
    signedUp()

  event signedUp()

test "Customers"
  given
    for i in range(3)

      [c].SignUp() as c
```

## E0901

Personal data flows into a place not marked personal: a field, an event argument, an external request parameter or a projection field. Such a value is not encrypted and not erased by forget. Mark the place personal.

```rr
actor Customer
  id uuid
  phone string? personal

  command(self) SignUp(phoneNumber string personal)
    signedUp(phoneNumber: phoneNumber)

  event signedUp(phoneNumber string?)
    phone = phoneNumber
```

```rr
actor Customer
  id uuid
  phone string? personal

  command(self) SignUp(phoneNumber string personal)
    signedUp(phoneNumber: phoneNumber)

  event signedUp(phoneNumber string? personal)
    phone = phoneNumber
```

## E0902

The place holds personal data of one subject, but data of another subject flows in. Subjects have different encryption keys: forgetting one must not erase another's data. Name the right subject with personal(field).

```rr
role admin

actor Customer
  id uuid

aggregate Order
  id uuid
  customer Customer.Id?
  phone string? personal(customer)

  command(admin) Fill(p string personal)
    filled(p: p)

  event filled(p string? personal)
    phone = p
```

```rr
role admin

actor Customer
  id uuid

aggregate Order
  id uuid
  customer Customer.Id?
  phone string? personal(customer)

  command(admin) Fill(p string personal(customer))
    filled(p: p)

  event filled(p string? personal(customer))
    phone = p
```

## E0903

A command parameter receives personal data but is not marked personal. Command arguments end up in engine logs and traces; marking them personal tells the engine to hide them.

```rr
actor Customer
  id uuid
  phone string? personal

  command(self) SignUp(phoneNumber string personal)
    [id].remember(note: phoneNumber)

  command remember(note string)
    return
```

```rr
actor Customer
  id uuid
  phone string? personal

  command(self) SignUp(phoneNumber string personal)
    [id].remember(note: phoneNumber)

  command remember(note string personal)
    return
```

## E0904

After forget, a subject's personal data reads as none, so a personal entity field and a personal event argument must be optional (T?).

```rr
actor Customer
  id uuid
  phone string personal
```

```rr
actor Customer
  id uuid
  phone string? personal
```

## E0905

Personal values are stored encrypted: an index on them supports equality only (== and in). Sorting, ranges and desc on a personal field are not possible.

```rr
actor Customer
  id uuid
  phone string? personal

  index byPhone(phone desc)
```

```rr
actor Customer
  id uuid
  phone string? personal

  index byPhone(phone)
```

## E0906

The engine encrypts a personal projection field with its subject's key, and the subject is stored in another projection field (personal(driverId)). A projection operation that sets the personal field must set the subject field too: an asynchronous projection is written after commit, and the subject cannot be read from the stored row while encrypting.

```rr
actor Driver
  id uuid
  name string? personal

  command(self) Rename(newName string personal)
    DriverCard(id: DriverCard.Id(id), driverName: newName)

projection DriverCard
  id Driver.Id
  driver Driver.Id?
  driverName string? personal(driver)
```

```rr
actor Driver
  id uuid
  name string? personal

  command(self) Rename(newName string personal)
    DriverCard(id: DriverCard.Id(id), driver: id, driverName: newName)

projection DriverCard
  id Driver.Id
  driver Driver.Id?
  driverName string? personal(driver)
```
