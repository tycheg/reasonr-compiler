## Deviations

| Stage | Deviation | Why |
|---|---|---|
| P1 | The engine keeps a value-level request, `kind.LeasedRequest`, which embeds the ready `port.LeasedRequest`, and an internal transport (`internal/ports.Transport`) that gets it; a plugin's transport is wrapped (`ports.Plugin`) and gets the ready request | The built-in HTTP transport encodes the values with its codec and the fakes of test mode run them; decision 4 leaves them that, and plugins see no compiler type |
| P1 | `kind` registers kinds and drivers through a leaf, `internal/kindreg`, which holds them as `any` | The engine's registry needs the kind types (the catalog, the tool), so `kind` cannot import it; the leaf keeps the read side out of the public API |
| P3 | The distribution module appeared in P3, not P5: `engine/cmd/reasonrd` moved to `dist/` together with the model-level tests that left the adapters | The tests needed a module that may require everything; P5 then added the manifest |
| P3 | `kind/kindtest` gives a distribution's tests the server (`StartServer`, `Serve`, `Scenarios`, `Call`, `Buffer`), the configuration check (`OpenConfig`), tokens (`SignToken`, `TokenVerifier`), `DialWebSocket`, `FreeAddr`, `PublishedModel` | The end-to-end tests used the engine's internal packages while they lived in the engine directory |
| P2 | The suites found two deviations of MongoDB from the contract: timers leased by the scenario clock came in the order of the real moment, and a table of `Layout.Rewrite` that is not personal was not rewritten. Both are fixed; a rewrite of a type no longer personal still drops the ciphertexts of unchanged documents | — |
