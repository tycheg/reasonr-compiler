Deviations from the plan made during the implementation:

1. **E0010 (a positional argument) is reported by type checking, not by the parser.** Built-in functions, conversions and value methods are called positionally in the RFC (`round(x, 2)`, `decimal(d)`, `OrderMart.Id(id)`, `declinedBy.with(d)`), so the parser accepts any arguments (`Arg.Name == nil` — positional), and stage 6 checks the ban for commands, events, errors and constructors.
2. **New syntax codes** beyond those listed in §6.5: E0008 (interpolation), E0009 (escape sequence), E0013 (too many errors), E0014 (the left side of an assignment), E0015 (unexpected indent), E0016 (no body), E0017 (a comparison chain), E0018 (a repeated section), E0019 (`tenant` not first), E0020 (the order of test sections), E0021 (the order of search sections). Section order is checked already in the parser, because the order of nodes in the tree depends on it.
3. **Golden files live in the `testdata/` of each package** (idiomatic for Go), not in a common root `testdata/`.
4. **The property of the lexer fuzz test** is: tokens are ordered and do not overlap, `INDENT`/`DEDENT` are balanced, and without errors every non-space byte is covered by a token or a comment. Whitespace is not kept in trivia.
5. **`examples/` are generated from the RFC**: `go test ./examples -update`. The bank and acme tenant blocks in the RFC got path headers (`# bank/bank.rr`, `# taxi/tenants/acme/order.rr`).
6. **Nodes:** `BreakStmt`/`ContinueStmt` are merged into `BranchStmt`; added `ParenExpr` (the formatter needs it), `AllExpr` (`all Order` in migrations), `LetDecl` (top-level fixtures); the target of a view action is `ActionItem.Target` (`SelectorExpr`).
7. **The `on` ambiguity:** a member `on name` is a reaction only if an indented body follows; otherwise it is a field `on` of type `name`.
8. **Empty lines in the formatter.** Instead of "one empty line between members of different kinds" the rule is: the author's empty lines are kept (several in a row become one, at the start of a block they are removed), and declarations and members with a body (`command`, `event` with a body, `query`, `rule`, `on`, methods, every top-level declaration with a block) are always separated from their neighbors by an empty line. A strict "by kind" rule would break the grouping in the RFC examples (a field and `check` in `value Money`, `index` after the fields).
9. **Trailing comments.** Consecutive lines with trailing comments are aligned to one column: not left of the column the author chose, and no closer than two spaces to the code. This keeps the manual alignment of the RFC examples.
10. **Strings with interpolation** are printed as in the source: the formatter does not touch escapes and the expressions in `{…}`.
11. **A broken list** (arguments, parameters, `[…]`) is printed one element per line with a comma after the last one and the closing bracket on its own line; a list broken by hand that fits in 120 characters is joined back into one line. A list with comments inside is always broken. In the RFC the `placed(…)` call in `Order.place` is rewritten this way — it was longer than 120 characters.
12. **`##` documentation and the formatter.** A doc comment at the end of a line belongs to the declaration that starts on it, so the formatter does not move such comments between lines: a comment on the line of an opening bracket stays there, a list with `##` on the line of the closing bracket stays broken, and a group of `##` right above the next line of code does not move into the tail of the previous block. The parser now treats `\r` as a space when it decides whether `##` stands on its own line — as the lexer does.
13. **What a module is.** A module is the `*.rr` files at the root of a directory and `tenants/<name>/*.rr`; nested directories are not part of the module. `reasonr check dir` looks for modules recursively: a directory with `*.rr` files or with `tenants/` is a module, otherwise its subdirectories are walked (so `reasonr check examples` checks `taxi` and `bank` separately). A single file is checked for syntax only.
14. **E10xx codes.** E1001 is reported both when the header is missing and when the name does not match the directory (with a fix). Added E1008 (`tenant` in a base file) and E1009 (`extend`/`exclude` in a base file).
15. **Merging.** An extension member that conflicts with a base one (E1003) and a reaction to an event that does not exist (E1006) do not get into the effective model, so they cause no error cascade. Repeats inside the extension itself are stage 5's concern. `on` may react to an event declared in the same extension. An overriding rule takes the place of the base one. Rule signatures are compared by the names and types of the parameters and the result type. The origin of a node is `Program.FromTenant(node)`: a model is built for one tenant, so the name need not be stored.
16. **Symbols live in `compiler/types`** (`Decl`, `Var`, `Method`, `Index`, `EnumValue`) next to the types, as in `go/types`: otherwise `types.Enum{Decl *sema.Type}` of §11.1 would be an import cycle. `sema.Info` holds the tables: declared types, roles, resolved type expressions, access, member owners.
17. **E01xx codes.** E0105 stays for enum ambiguity (stage 6, §2 item 3). Added: E0107 — unknown type (with a hint of the closest name), E0108 — a built-in name (`id`, `now`, `today`, `after`, `hasErrors`, `me`, `caller`, `self`) as a field, parameter or variable, E0109 — the number of type arguments, E0110 — no `id` line (entities, actors and projections must have one), E0111 — an invalid `id` (not `uuid`/`sequence`/`string`/a value object; `id Order.Id` not on a projection, or based on a projection). Of E06xx, E0601–E0604 and E0606 are reported here, during resolution; E0605 and W1010 stay with stage 7.
18. **Namespaces.** A value object's fields and methods share one namespace (both read as `x.name`). Parameters of errors and notifications may coincide with fields: they have no body, and by RFC §10.2 the parameters of a unique index error are named after the index fields. In an `on` reaction the event arguments are taken as names.
19. **Name style.** Enum values are camelCase, as in RFC §6.2; the `Currency` example in the RFC and the examples is rewritten as `rub`, `usd` (the author's decision). For commands and queries the case sets visibility, so there is nothing to check.
20. **An entity name in a type position** resolves to `Record` (`let o Order? = [orderId]`); stage 6 checks where such a type is allowed.
21. **The boundary between stages 6 and 7.** Stage 6 checks the bodies of methods, `on` reactions, migrations, `check` invariants, default values and test `let`s. Test steps (`given`/`when`/`then`) and view items are checked in stage 7 together with E07xx and E08xx: they have their own semantics (partial arguments, `item`, `as`, `matches`).
22. **Stage 6 codes.** E0010 (an argument without a name) is reported by type checking (see item 1). E02xx: E0201 unknown name, E0202 incompatible types, E0203–E0205 arguments, E0206 the type cannot be determined (`none`, `[]`, `[:]` without context), E0207 the value may be none, E0208 an inapplicable operator, E0209 no such member, E0210–E0212 default values, E0213 the value is not used, E0214 an invalid statement (the text says which), E0215 `new` for `id string`/a composite, E0216 identifier conversion, E0217 fields of another entity. E03xx: E0301 a field outside an event, E0302 not an assignment in an event, E0303 an action not allowed in the context (the message names the context and the action — one code for the whole table of §11.6), E0304 a built-in value is not available. E0507, E0508, W1002 — as in §11.8.
23. **Required arguments.** A parameter or a field is required if it has no `= value` and its type is not optional (the RFC does not say). For a projection upsert only `id` is required.
24. **Literals and arithmetic.** An integer literal takes any expected numeric type, a fractional one — `decimal` or `float`. Besides numbers: `string + string`, `timestamp ± duration`, `timestamp − timestamp → duration`, `duration ± duration`, `duration * int`.
25. **Fields by bare name** are read in commands, events, rules, value methods, `check` and `on` reactions. In a query (it belongs to the type) — only in search sections; `[x]` in a query is a record, in a command a reference. `[Order]` without sections has type `list<Order>` for now; the restrictions on search are stage 7.
26. **`me`** has the identifier type of the only actor in the access list; with several actors in the list `me` is not available.
27. **Codes E0206–E0209** follow the table of §12.8 (`[x].cmd` with an optional `x`, an extra `?.`, the argument of `delete`, the target of `to`); the meanings stage 6 had given them moved to E0218–E0221.
28. **Where stage 7 codes are reported.** E07xx and E08xx are reported while type-checking views and tests in `sema` (they need typed expressions: partial arguments, `item`, `as`, `matches`), E0402 — while checking `schedule`. The analyzers of `compiler/check` are `callgraph` (E0401), `queries` (E0501–E0510, E0905), `unique` (E0511, E0512), `access` (E0605, W1010), `pii` (E0901–E0904, W1020, W1021), `lint` (W1001, W1003–W1006). The call graph and the chosen indexes are analyzer results for the IR and `reasonr graph`.
29. **Views.** Root views are views without parameters; W1011 — a view with parameters that no other view opens. E0702 — a required argument of an identifier type that is not passed: it cannot be entered in a form. `item` is an element of the query result (`page<T>`, `list<T>` → `T`).
30. **Tests.** `error` and `notification` in `then` are looked up by name across the whole model: nested commands raise them. Same-named ones in different types must have the same parameters. Built-in errors: `forbidden`, `invalidArgument(path, rule)`, `internalError`.
31. **Queries.** `!=` and `is not none` — E0503; `[Type]` without sections — E0505; any `[x]` with a record of another type in a query — E0510. E0504 carries a fix: inserting `index …` after the last field or index.
32. **Personal data.** A personal parameter of an external request accepts the data of any one subject. Query results and notifications are not sinks. Variable labels are flow-insensitive; results of query calls are not labeled.
33. **W1007 ("a public command without a view") is removed** by the author's decision: it would fire on the external system response commands of the RFC examples (`DriverFound(matching)`, `PaymentCaptured(payments)`, `Freeze(compliance)`), which are not called from the interface. Code W1007 is unused.
34. **`reasonr check --all-tenants`** removes duplicate diagnostics: tenant models include the base files.
35. **The IR refers to types, methods, fields and indexes by name** (`Order.place`, `field status`, `find Order by byCustomer`). The numbers `TypeRef`, `FieldRef`, `MethodRef`, `IndexRef` are assigned by the schema (stage 9) and by bytecode generation: so the IR does not depend on the schema and reads without tables.
36. **Operands and constants.** An operand is a slot or a constant from the function's pool (`eq.enum r1, OrderStatus.searching`, `move 0`): there is no separate `const` operation. Parameters take the first slots; there is no `param` operation. `T` and `T?` have the same representation, so there is no `opt.wrap`: absence is checked by `opt.isnone`, and `eq`/`ne` accept none (none equals only none). An instruction's operands are read before its result is written (`r4 = add.i64 r4, 1`).
37. **`on` reactions.** Lowering does not insert reaction calls at the end of a command: which events are raised and in what order is known only at run time (branches, loops). Before every `ret` of a command or a reaction that may raise an event with reactions there is a `react` — "run the reactions to the events this function raised, in the order raised"; the reaction table is `Program.Reactions`.
38. **Applying an event.** In an `apply` function `field` reads the state before the event and `set` writes the new one: assignments see the previous field values ("from the current fields", RFC §12).
39. **Default values.** For internal calls (commands, events, notifications, errors, rules, constructors, queries) lowering fills omitted parameters with their `= value` or none. For calls from outside the schema supplies the defaults (stage 9). A projection upsert and test checks pass only the arguments written.
40. **Built-in values** `id`, `now`, `today`, `me`, `caller` are computed once at the start of a function (a call of one's own command is addressed by `id` too), `hasErrors` and `after` — on every access. `[x]` in a command condition is `ref.exists`, elsewhere `ref.load`; in a query `rec.load`.
41. **Search** is `find` with a `FindSpec` template (type, index, conditions with operands, sort, `page` or `limit`), then a `select` loop with `coll.append`; for a page the result is `page.with` (the found page with new items). A search without conditions and sorting runs without an index: the engine picks the plan. The parsed search is a result of the `queries` analyzer (`check.Search`); `check.Analyze` returns the analyzer results.
42. **The standard library** is `intrinsic`: properties and methods prefixed with the receiver kind (`str.length`, `list.with`, `map.get`, `page.items`, `caller.roles`), functions by name (`decimal`, `round`), interpolation joining — `str.concat`. Internal loop operations — `coll.len`, `coll.get`; a loop over a map goes over `map.keys`.
43. **Tests** — a function per test: shared `let`s, the test's `let`s, `given` steps (`test.cmd`, `test.query`, `test.time`), the `test.when` mark, the `when` step, the checks `expect.notify`, `expect.error`, `expect.request`, `expect.matches` with the arguments written. `as` is an actor operand or a role; `via` is a UI contract and does not get into the IR. The `check` invariants of a value object are a function `Type.check` returning bool.
44. **Optimizations.** Constant folding happens during lowering: integers without overflow, exact decimals, durations, string joining, comparisons; division and floating point (except unary minus) are not folded. After lowering: a branch on a constant → a jump, jumps threaded through empty blocks, removing unreachable blocks (block order — reverse postorder), removing unused slots and constants. Temporary slots live until the end of a language statement and are reused by type; a value computed by the last instruction is written straight into the variable.
45. **E0101 for migrations and tests too**: a repeated migration name or test title was not detected before and gave two IR functions with one name.
46. **The binary IR format**: `RRIR`, a version, varints and length-prefixed strings; `Decode` verifies the program (`Verify`) and does not panic on any input (fuzz `FuzzDecode`). `FuzzLower` checks that any error-free model lowers to a valid IR.
47. **The boundary types live in the root package** `github.com/tycheg/reasonr` (`schema.go`), not in a `reasonr/` subdirectory: the import path `…/reasonr/reasonr` is awkward. For now it holds only the schema; `Value`, `UnitOfWork`, `Env` come with the interpreter.
48. **The schema differs from RFC §30.5:**
    - the type of a field, parameter and result is a structure `Type{Kind, Ref, Elem, Key, Optional}` instead of a `TypeRef` + `Kind` pair and an `Optional` flag on the field: otherwise `list<Driver.Id>`, `map<K, V>` and optional elements could not be written; the kinds `page` and `pageRequest` are added;
    - a default value is a `Literal` (the canonical form of a scalar, value object fields, collection elements), not a `Value`: a `Value` refers to the arena and cannot be written into the schema file;
    - added the method kind `method` (value object methods), `MethodInfo.Tenant`, `TypeInfo.View` (access; actions with a method number, the names of the passed arguments and a control; child views) and `TypeInfo.Control` (the input type of a control). The expressions of view arguments (`item.orderId`, `new Order.Id`) are not in the schema yet — the UI runtime will need to evaluate them;
    - `Schema.Migrations` — the names of the manual migrations (the compatibility check needs them); `Version` is assigned by the engine, the compiler leaves 0;
    - in JSON kinds are written by name (`"kind": "entity"`).
49. **Numbering.** Types — by kind, then by name, from 1 (0 means "no type", as in `BusinessError.Owner`). Fields, parameters and indexes — in declaration order from 0, tenant extension fields at the end: so the record layout does not change when a tenant adds fields. Methods — by kind, then by name, from 0.
50. **The subject of a personal parameter** of a command or an event is the type itself (as in the `pii` analyzer); for an external request parameter without a subject `SubjectType` is 0 ("any subject"). Default values (explicit ones and the zero values of types) are computed by `sema` and put into `Info.Defaults`.
51. **Compatibility rules** (`compiler/compat`) beyond the table of §14.2. Matching goes by name, for fields by `was` too. E1101 is also reported when the kind of a type or the identifier strategy changes, an enum value is removed, the type of a value object field changes. A migration cannot be tied to a specific change, so E1101 is not reported if the new version has a new migration. W1102 — also when an entity, actor or projection is removed. W1103 — a new unique index, or an index that became unique. E1102 — removing or renaming an event, removing an argument, changing its type (except `T` → `T?`), a new argument that has no default value and is not optional. The report is diagnostics as text or JSON (`--format json`).
52. **`int` is 32 bits** (RFC §7.1): constant folding does not fold `int` expressions whose result does not fit in 32 bits.
53. **The common entry point is the package `compiler`**: `Open`/`OpenFS` load a module, `Module.Model(tenant)` builds and checks a model, `Load` does both. `Model` holds the program, `Info`, the analyzer results and all diagnostics. `check`, `build` and the tools go through it.
54. **`reasonr explain`** describes a type (fields, indexes, members) or a method: the header and visibility, the documentation, access, checks (branches with errors, an exit or a result — with the condition text), actions in order (events with the fields they change, commands with their target, notifications, timers, external requests, projections, forget), who calls it (commands, reactions, timers, migrations) and in which views the method is available. For an event — its fields, the commands that raise it, and the reactions.
55. **`reasonr graph`** draws the nodes "command" (public ones highlighted), "event", "reaction", "external request", "projection" in the colors of an Event Storming board, and the edges "raises event", "calls command", "timer", "request", "updates projection", "reacts to event". `--entity` keeps the commands and reactions of one type and what they are connected to.
56. **`reasonr pii`** groups the map by subject: personal fields and parameters, flows (where a value goes: an event, a field, a command, an external request, a projection, a notification, a query result) and the places of `forget`. The map is built by the `pii` analyzer (`check.PIIMap`); flows into notifications and query results are recorded in the map but not checked (see item 32).
57. **`reasonr diag explain`.** The explanations live in `compiler/diag/explain/*.md`, not in `codes.go` (the field `Spec.Explain` is removed): every code has a text, an example with the error and a fix; an example may consist of several files (tenants) or two model versions (`old/`, `new/` for E11xx). The test `compiler.TestExplanations` runs every example through the compiler: the example reports exactly its code (warnings — without errors), and the fix compiles without errors and is already formatted. Only E0013 is not checked (it needs 50 errors). `reasonr diag list` lists the codes.
58. **Cascades found on the explanation examples:** a comparison chain (E0017) and a search with a repeated or misplaced section (E0018, E0021) become `BadExpr`; a `tenant` header in the wrong place (E0019) does not also cause E1001; an extra argument with a hint (E0204) is not counted as missing (E0203); an extra `?.` (E0207) does not make the result optional.
59. **`AGENTS.md`** — the agent's work loop (edit → `fmt` → `check --format json` → fixes → `diag explain`), exit codes, the JSON diagnostics format version 1 with a description of the fields, the tools and frequent mistakes.
60. **The LSP protocol is our own thin JSON-RPC layer** (`lsp/jsonrpc.go`, `lsp/protocol.go`) with structures only for the methods used, not `go.lsp.dev/protocol` (§17.1 named it the default option): the server handles about fifteen methods, and the core and the CLI stay free of external dependencies. The decision was made without the author's confirmation; if the full protocol is needed, the layer can be replaced without changing the handlers. Positions are in UTF-16 (the LSP default encoding).
61. **The parse cache** is `module.Cache` and `module.LoadCached` (`compiler.OpenCached`): on every check the module files are reread, but only those whose text changed are reparsed. The file set (`source.FileSet`) only grows — every edit adds a new version of a file — so the server recreates the set and the cache when the set is larger than 4 times the live text of the module plus 1 MB.
62. **The workspace module** is the directory of the file; for `tenants/<name>/*.rr` — the directory two levels up; `reasonr.yaml` is not supported (the language has none). Open documents override the files on disk, including new ones that are not on disk yet. The base model and the models of all tenants of the module are checked; diagnostics of base files come from the base model, of tenant files — from the tenant's model; they are published for every file of the module.
63. **Checking after an edit** — 150 ms after the last edit, the whole module. A positional request (hover, definition, completion…) on a stale snapshot checks the module right away without waiting for the pause. Measured (`BenchmarkEdit`, Apple M1 Max): a 10.4k-line module (10 files, 160 entities) — about 10 ms from an edit to diagnostics; the 100 ms goal is met with a margin, per-entity analysis is not needed.
64. **Completion** rechecks the module with a text where a placeholder `_` stands at the cursor when no name has been started (only the file's model; the module snapshot does not change): so `order.`, `placed(` and `status == ` parse as expressions, and type checking gives the type before the dot, the called method and the type of the other side of a comparison. Offered: after `.` — fields, value methods, built-in properties and methods (`sema.BuiltinMembers`); after `[x].` — the entity's commands; after `Type.` — enum values, `Id`, queries and external system requests; in a call — the names of the arguments not passed yet; when an enum is expected (`==`, `!=`, `=`, `let x T =`, a named argument) — its values, for `bool` — `true`/`false`; in `where` — the record's fields, the fields an index starts with first and with the index name; otherwise — the variables, parameters, fields and methods of the type, types, built-in names and keywords by place (top level, type members, statements, tests, views, types). Methods are inserted as a snippet with the required arguments.
65. **Hover, definition, references** resolve the name under the cursor: local variables, parameters (in the body, in the declaration, argument names), fields (also through `x.field`, in index and search sort keys, in access lists), enum values, types, methods (calls, declarations, `on`, the unique index error, view actions, `then` checks), indexes, roles, built-in names. Hover shows the declaration, whose member it is, the `##` documentation and the personal data subject (from the `pii` map). References are searched in every file of the module, in tenant files — by the tenant's model; references from extensions to base declarations match by the pointer to the name in the declaration, because the base trees are shared.
66. **Semantic highlighting**: the kinds `class` (entities, actors, projections), `struct`, `enum`, `interface` (external systems), `type` (views, roles), `enumMember`, `property`, `parameter`, `variable`, `function`, `method` (commands), `event` and our own `error`, `notification`; the modifiers `declaration`, `public`, `private` (commands and queries), `personal`, `defaultLibrary`. The VS Code extension declares its own kinds with their parents.
67. **Quick fixes** are all diagnostic fixes with edits (including edits in other files); fixes without edits are appended to the message as hints, notes with a place become related information (`relatedInformation`).
68. **"Explain command"** — the server command `reasonr.server.explain` (`workspace/executeCommand` with a URI and a position) returns the `reasonr explain` text for the method or type under the cursor; the extension (its own command `reasonr.explain`) opens it beside the editor. The server and extension command names differ: the VS Code LSP client registers the server's commands in the editor, and the same name breaks the client start.
69. **The VS Code extension** (`editors/vscode`): a TextMate grammar (checked by `npm test` on every example), language settings (comments, brackets, folding by indentation, indentation after block headers), an LSP client on `vscode-languageclient`, the setting `reasonr.server.path`, the commands Format, Explain command and Restart language server. Built with `make vscode`, a separate job in CI (build and grammar check). The extension is not bundled into one file — `vsce` warns about it, which does not affect how it works.
70. **Not done in stage 12:** rename (planned for later), request cancellation (`$/cancelRequest` is ignored: a check takes tens of milliseconds), the tree-sitter grammar (planned for later).
